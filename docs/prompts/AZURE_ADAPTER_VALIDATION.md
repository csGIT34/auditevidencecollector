# Ready-to-use workplace validation and deployment prompt

Use after the Azure adapter has been implemented. This prompt does not itself authorize cloud access or provisioning.

---

Validate the Azure Blob adapter in this cloud-governance repository and prepare a concrete deployment handoff. Read `docs/WORKPLACE_AZURE_HANDOFF.md`, `docs/LOCAL_ARCHIVE_PDF.md`, the actual storage adapter/configuration, `archive.py`, `pdf_report.py` and all related tests. Inspect current git state and preserve others' changes. This task must retain the accepted single-PDF workflow and deterministic core; it is not a collector expansion or infrastructure redesign.

The local reference adapter exposes `put_new(key, bytes)`, `read(key)` and `keys(prefix)`. The Azure implementation must preserve atomic create-if-absent writes, exact-key reads, complete scoped listing, portable keys, explicit failures and schema/version identity. Review the actual SDK request conditions, including multipart block commits, concurrency and lost-response handling. Existing-key collisions must never overwrite. Error handling must not leak credentials or raw sensitive payloads. Check credential-chain tenant/cloud constraints and least-privilege data access separately from ARM collection access.

Run the complete offline suite and adapter contract tests. Verify all 23-service applicability records and the packaged scope outline remain consistent, and that executable assessment coverage is still described honestly. Demonstrate multiple archived runs/reports with sanitized fixture data. Select an older exact run for PDF generation while preventing collector/evaluator/current-context access; compare saved bytes/hashes before and after and prove the newer run is not substituted. Test corrupted/missing objects, denied/listing-incomplete reads, timeout/throttling, every object/manifest failure stage and failed failure-marker writes. Intent-only/failure-marked publications must remain incomplete; final manifests are last.

Generate a self-contained sample PDF. Extract text and visually render/inspect all pages. Confirm scope, collection window, original assessment time, new generation time/version, control/check criteria, actual observed facts, findings, dependency references, errors, missing/manual/shared/inherited evidence and limitations are inside the same document. Internal indices/links must work, long fields/tables must fit and all saved observations must be accounted for. Auditors must not need a database, JSON files, Blob links or a separate index. Technical configuration is not evidence that processes operated over an entire audit period.

Prepare a deployment checklist using actual code/configuration names. Identify unresolved organization-specific inputs: cloud/tenant/identity, existing account/container/prefix, data-role scope, runner and private endpoint/DNS/network path, allowed package versions, classification/recipients, retention/legal holds, access monitoring, cost scope and change authorization. Do not fill these with guessed or personal values. No live cloud action is authorized solely by this prompt. If explicit live authorization and inputs are available, perform only the bounded nonproduction synthetic-data validation permitted by them; otherwise finish the offline validation and list the remaining live checks.

Do not create accounts/containers, grant roles, modify network controls, upload real organization evidence, delete protected archives, or enable/lock immutable retention unless separately and explicitly authorized for that exact operation. Retention duration remains organization-defined. Review policy compatibility without making irreversible changes. Preserve unique logical keys and no-overwrite even when Azure versioning/immutability is enabled.

Deliver test evidence and a concise readiness decision: what passed offline, what passed against live Azure if authorized, what remains unverified, any actual defects and fixes, sample PDF location, required operator configuration and rollout/rollback steps. Rollback means reverting application/configuration or selecting local storage; it must not rewrite/delete historical evidence. Clearly distinguish the completed NIST research, implemented adapter/pipeline, unimplemented control collectors and any remaining live deployment work.
